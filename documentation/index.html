Software Engineer Portfolio: Astro theme

Version 1.0.0. A dark, technical portfolio and landing page for independent software engineers, consultants and small studios.

Introduction

The theme gives you a landing page, case studies, services, an about page, a writing section, a project enquiry form, a contact form, legal pages and error pages. Pages are pre-rendered to static HTML for speed; the two forms and a health check run on a small Node server that ships with the theme.

The demo person, Mira Castell, and all clients, quotes and figures are fictional. Replace them with your own before you publish.

Requirements

  • Node.js ^22.23.4, ^24.16.0 or >=26.3.0. Version 24 is recommended (see .nvmrc).
  • Yarn 1, enabled with Corepack (bundled with Node).
  • For production: any host that runs Node or Docker containers.

Installation

corepack enable
yarn install --frozen-lockfile
cp .env.example .env
yarn dev

Open http://localhost:4321. Changes to pages, data files and styles reload automatically.

Before deploying, run the full check, which lints and builds the site:

yarn run check

Use yarn run check, not yarn check: the latter is a built-in Yarn 1 command.

Editing content

Data files

  • src/data/profile.js: hero text, bio, portrait, highlights, client names, experience, toolbox and principles.
  • src/data/projects.js: case studies. Each needs a unique slug, an imported cover image, a summary, stack, outcomes, challenge, approach and result. featured: true shows it on the home page.
  • src/data/services.js: services with price, inclusions, process steps and FAQs. Set priceFrom: null to hide a price.
  • src/data/navigation.js: menus, the header button, footer columns and the optional announcement bar.

Only publish outcomes and figures you can stand behind. The demo figures are invented.

Articles

Add a Markdown file to src/content/articles/. The file name becomes the URL (/journal/<file-name>). The build fails with a clear message if the front matter is invalid.

---
title: "Your article title"
excerpt: "One or two sentences for cards and search results."
category: "Engineering"
publishedAt: 2026-11-01
updatedAt: 2026-11-15        # optional
author: "Your Name"          # optional
image: "../../assets/images/journal/your-image.jpg"
imageAlt: "Describe the image"
featured: false              # true leads the writing page
---

Write your article in Markdown. Code blocks are highlighted automatically.

Colours, fonts and images

Colours and spacing

All colours, spacing, radii, shadows and type sizes are CSS variables in src/styles/tokens.css. Change --color-accent to recolour the whole site. Check text contrast stays at WCAG AA (4.5:1) against --color-background.

Fonts

Fonts are configured in astro.config.mjs under fonts and are downloaded at build time, so visitors never contact Google. Change name to any Google Fonts family and adjust weights. Code uses the system monospace stack (--font-mono).

Images

  • Replace src/assets/images/portrait.jpg with your photo (4:5 works best) and update portrait.alt in profile.js.
  • Project covers (16:10) live in src/assets/images/projects/; article images (16:9) in src/assets/images/journal/. Astro resizes and converts them automatically.
  • The social sharing image is public/images/og-default.jpg (1200×630).
  • Favicons: favicon.svg, favicon.ico, apple-touch-icon.png, icon-192.png, icon-512.png in public/.

Forms and email

The project enquiry form (/hire) and contact form (/contact) validate in the browser and again on the server using the same rules (src/lib/forms/). They include a hidden honeypot field and a per-visitor rate limit. Configure at least one delivery transport for production; without one, the server returns an error that shows your phone number and email, so submissions are never silently lost.

Webhook

Set FORM_WEBHOOK_URL (and optionally FORM_WEBHOOK_SECRET, sent as a bearer token). Each submission is POSTed as JSON:

{
  "id": "PRJ-2A4223BC37",
  "type": "enquiry",
  "submittedAt": "2026-11-01T12:47:12.852Z",
  "title": "Project enquiry from Sam (Acme)",
  "replyTo": "sam@example.com",
  "fields": [
    { "label": "Project type", "value": "Back end, APIs or integrations" },
    { "label": "Budget", "value": "£10,000 to £25,000" }
  ],
  "data": { "name": "Sam", "email": "sam@example.com", "projectType": "platform", "...": "..." },
  "site": "Your Name",
  "text": "Plain-text summary for chat tools such as Slack"
}

Email with Resend

  1. Create an account at resend.com and verify your sending domain.
  2. Create an API key.
  3. Set RESEND_API_KEY, FORM_EMAIL_TO (comma-separated) and FORM_EMAIL_FROM (e.g. Your Name <web@your-domain.com>).

Replies go straight to the visitor: the email's reply-to is their address. If both transports are set, the submission succeeds when at least one delivers it.

Changing the options

Edit project types, budgets and timelines in src/lib/forms/enquiry.js, and contact topics in src/lib/forms/contact.js. The browser and server pick up the change together.

Deployment

The pages are static, but the forms and /api/health need a server. Node and container hosts run the included server unchanged, so they're the simplest choice. Serverless hosts need a different Astro adapter, which takes a few small changes. A static-only host won't run the forms.

PlatformHow it runsCode changes
DigitalOcean App Platform, Render, Railway, Fly.io, VPSNode server or containerNone
Vercel, Netlify, Cloudflare WorkersServerless functionsSwap the adapter

Always set PUBLIC_SITE_URL to your HTTPS domain at build time, and rebuild if it changes; the server then trusts forwarded headers from that domain only, which keeps rate limiting accurate behind a proxy. Configure a form transport as well, or production forms will return an error.

DigitalOcean App Platform

App Platform builds the included Dockerfile, so no code changes are needed. Choose a Web Service, not a Static Site, because the forms need the server.

  1. Push the theme to GitHub, then choose Create App in DigitalOcean and select your repository and branch. App Platform uses the Dockerfile in the repository root automatically.
  2. Set the service's HTTP port to 3000.
  3. Set the health check path to /api/health.
  4. Add PUBLIC_SITE_URL with the scope Run and build time. It's passed to the Docker build as a build argument.
  5. Add your form variables with the scope Run time, and encrypt secrets such as RESEND_API_KEY.
  6. Deploy, then add your domain in the app's settings. If you started with the ondigitalocean.app address, update PUBLIC_SITE_URL and deploy again.

To keep the same setup in a file, save this as .do/app.yaml and run doctl apps create --spec .do/app.yaml:

name: portfolio
services:
  - name: web
    github:
      repo: your-account/your-repository
      branch: main
      deploy_on_push: true
    dockerfile_path: Dockerfile
    http_port: 3000
    health_check:
      http_path: /api/health
    envs:
      - key: PUBLIC_SITE_URL
        value: https://www.your-domain.com
        scope: RUN_AND_BUILD_TIME
      - key: RESEND_API_KEY
        scope: RUN_TIME
        type: SECRET
        value: replace-me
      - key: FORM_EMAIL_TO
        scope: RUN_TIME
        value: you@your-domain.com
      - key: FORM_EMAIL_FROM
        scope: RUN_TIME
        value: Your Name <web@your-domain.com>

Don't commit a real secret to this file. Keep the placeholder and set the value in the dashboard. If the build fails on /var/run, DigitalOcean's fix for Alpine images is to add RUN test -e /var/run || ln -s /run /var/run to the Dockerfile.

Render

New Web Service → connect the repository → Build command yarn install --frozen-lockfile && yarn build, Start command yarn start. Add environment variables, including HOST=0.0.0.0. Render sets PORT.

Railway

New project from the repository. Railway detects the Dockerfile; add PUBLIC_SITE_URL as a variable (it's passed as a build argument) and your form variables.

Fly.io

fly launch --no-deploy
fly secrets set RESEND_API_KEY=... FORM_EMAIL_TO=... FORM_EMAIL_FROM=...
fly deploy --build-arg PUBLIC_SITE_URL=https://www.your-domain.com

Set the internal port to 3000 in fly.toml.

VPS with Nginx or Caddy

PUBLIC_SITE_URL=https://www.your-domain.com yarn build
HOST=127.0.0.1 PORT=3000 yarn start   # run under systemd or pm2

Caddy:

www.your-domain.com {
    reverse_proxy 127.0.0.1:3000
}

Nginx:

server {
    server_name www.your-domain.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}

Docker

docker build --build-arg PUBLIC_SITE_URL=https://www.your-domain.com -t portfolio .
docker run -d -p 3000:3000 --env-file .env --restart unless-stopped portfolio

Or with Compose: fill in .env, then docker compose up -d --build. The container reports its health through /api/health.

Serverless platforms

Vercel, Netlify and Cloudflare don't run server.mjs, so each one needs its own Astro adapter. Replace the Node adapter in astro.config.mjs, including its options, as shown in the guide for your platform. yarn start and server.mjs then no longer apply.

What changes on serverless: the security headers in server.mjs no longer apply, so each guide adds them another way. The 64 KB form size limit is gone, and the host's own limit applies instead. Rate limiting is kept in memory, so each function instance counts separately and it's much weaker. If the forms attract abuse, add the platform's firewall or rate-limiting rules.

Vercel

yarn remove @astrojs/node
yarn add @astrojs/vercel

In astro.config.mjs:

import vercel from "@astrojs/vercel";

// Replace the existing adapter: node({ ... }) block with:
adapter: vercel(),

Add a vercel.json file for the security headers:

{
  "headers": [
    {
      "source": "/(.*)",
      "headers": [
        { "key": "Strict-Transport-Security", "value": "max-age=63072000" },
        { "key": "X-Content-Type-Options", "value": "nosniff" },
        { "key": "X-Frame-Options", "value": "SAMEORIGIN" },
        { "key": "Referrer-Policy", "value": "strict-origin-when-cross-origin" },
        { "key": "Permissions-Policy", "value": "camera=(), microphone=(), geolocation=(), payment=(), browsing-topics=()" }
      ]
    }
  ]
}

Commit and push, then import the repository in Vercel, which detects Astro automatically. Add PUBLIC_SITE_URL and your form variables under Environment Variables, deploy, and redeploy after changing PUBLIC_SITE_URL. Check that your Vercel plan's terms cover your use if the site promotes paid work.

Netlify

yarn remove @astrojs/node
yarn add @astrojs/netlify

In astro.config.mjs:

import netlify from "@astrojs/netlify";

// Replace the existing adapter: node({ ... }) block with:
adapter: netlify(),

Add a netlify.toml file for the build settings and security headers:

[build]
  command = "yarn build"
  publish = "dist"

[[headers]]
  for = "/*"
  [headers.values]
    Strict-Transport-Security = "max-age=63072000"
    X-Content-Type-Options = "nosniff"
    X-Frame-Options = "SAMEORIGIN"
    Referrer-Policy = "strict-origin-when-cross-origin"
    Permissions-Policy = "camera=(), microphone=(), geolocation=(), payment=(), browsing-topics=()"

Commit and push, then import the repository in Netlify. Add PUBLIC_SITE_URL and your form variables in the site's environment variables, then deploy. Netlify reads the Node version from .nvmrc. Open /projects, /services and /journal after the first deploy: each of these is both a page and a folder in the build output. If one returns a 404, set build.format to "directory" in astro.config.mjs.

Cloudflare Workers

Use Workers, as the Astro adapter no longer supports Cloudflare Pages.

yarn remove @astrojs/node
yarn add @astrojs/cloudflare
yarn add -D wrangler

In astro.config.mjs, use the compile image service, which optimises images during the build:

import cloudflare from "@astrojs/cloudflare";

// Replace the existing adapter: node({ ... }) block with:
adapter: cloudflare({
    imageService: "compile"
}),

Add a wrangler.jsonc file. The nodejs_compat flag lets the forms read their settings from process.env, and it needs a recent compatibility date:

{
  "name": "portfolio",
  "compatibility_date": "2026-10-01",
  "compatibility_flags": ["nodejs_compat"]
}

Add a public/_headers file for the security headers. Cloudflare applies it to static files but not to responses from the Worker, such as the form APIs:

/*
  Strict-Transport-Security: max-age=63072000
  X-Content-Type-Options: nosniff
  X-Frame-Options: SAMEORIGIN
  Referrer-Policy: strict-origin-when-cross-origin
  Permissions-Policy: camera=(), microphone=(), geolocation=(), payment=(), browsing-topics=()

Set your form variables, then build and deploy. PUBLIC_SITE_URL must be set in the build command because it's read at build time:

yarn wrangler secret put RESEND_API_KEY
yarn wrangler secret put FORM_EMAIL_TO
yarn wrangler secret put FORM_EMAIL_FROM
PUBLIC_SITE_URL=https://www.your-domain.com yarn build
yarn wrangler deploy

After you deploy

  • Open /api/health, which should return {"status":"ok"}.
  • Send a test message through /contact and /hire, and confirm it arrives.
  • Check that /sitemap.xml uses your domain, not localhost.
  • Run curl -I https://www.your-domain.com to confirm the security headers are present.

SEO and staging

  • Every page has a title, description, canonical URL, Open Graph tags and twitter:card.
  • Structured data: Person (with jobTitle, knowsAbout, sameAs) on every page, BlogPosting on articles, BreadcrumbList on detail pages.
  • /sitemap.xml and /robots.txt are generated at build time. Add new static pages to staticRoutes in src/pages/sitemap.xml.js.
  • For staging, build with PUBLIC_SITE_NOINDEX=true: every page gets noindex and robots.txt blocks all crawling.

Launch checklist

  • Your name, email, phone, city and social links in src/data/site.js
  • Your bio, portrait, experience and toolbox in src/data/profile.js
  • Real case studies with figures you can verify; demo projects removed
  • Your services and prices, or prices hidden
  • Demo articles replaced with your own
  • Favicons, manifest and social image updated
  • Privacy and terms reviewed, then showDemoContentNotice: false
  • PUBLIC_SITE_URL set to your HTTPS domain
  • A form transport configured and a test enquiry received
  • DEMO_MODE and PUBLIC_SITE_NOINDEX off
  • yarn run check passes

Troubleshooting

Canonical links point to localhost

Set PUBLIC_SITE_URL before building and rebuild. The build prints a warning when it is missing.

Forms say "We could not send your request"

No transport is configured, or all configured transports failed. Check the server logs for [forms] lines and your Resend or webhook settings.

"Too many requests" while testing

Each visitor can send five submissions per form every ten minutes. Restart the server to reset the counter.

Fonts look like system fonts

Fonts are downloaded during the build. Make sure the build machine can reach Google Fonts, then rebuild.

Build fails on an article

The message names the file and field. Usually a missing imageAlt, a wrong image path or an invalid date.

Updating the theme

Keep your content in src/data/, src/content/ and src/assets/, and your design changes in src/styles/tokens.css where possible; that keeps updates simple. Read CHANGELOG.md for each new version, compare the changed files and apply them with Git. Run yarn run check after updating.
